# 本地数据分析 Agent — 优化实施计划

日期：2026-07-26
依据：《项目优化分析报告》（docs/项目优化分析报告.md）+ 已确认范围
范围决定：后端执行 P0 + 安全的 P1（不改动图的控制流顺序）；前端执行安全修复 + ChatPage 重构改版；所有改动配套测试并在沙箱内实际执行验证。

## 0. 原则与回滚

所有修改直接写入本地工作区文件，不触碰 git 历史——每一处改动都可以用 `git diff` 审查、`git checkout -- <file>` 回滚。行为兼容优先：本轮不改变分析图的节点顺序与对外 API 契约；公开函数保留原签名（新增参数一律带默认值）。每个阶段完成后跑全量 pytest，红了先修再进下一阶段。

## 阶段一：环境与基线（沙箱内）

搭建 Python 虚拟环境、安装依赖、安装 PostgreSQL + pgvector、执行 001–016 迁移、导入 olist 数据、跑通现有测试套件，记录基线通过数。基线即验收对照：重构后不允许出现基线通过、现在失败的用例。

## 阶段二：后端基础设施（对应报告 §2.1、§2.2、P1）

**2a. Embedding 一次化。** `vector_retrieval.py` 三个检索函数与 `sql_memory_tools.py` 的记忆写入均接受可选 `vector=` 参数；`analysis_graph` 在检索节点前 embed 一次并存入 state 复用。外部行为不变，embedding 调用次数 4→1。

**2b. 数据库连接池。** `db/connection.py` 增加模块级线程安全有界连接池（保留 pg8000），`get_connection()` 契约不变（依旧是 contextmanager，autocommit），改为借出/归还；连接借出时做活性校验，损坏则重建。新增 `POOL_SIZE` 配置项，默认 5。

**2c. 日志批量化。** `run_repository.py` 新增 `create_tool_calls`（单连接 executemany）；`run_logger.py` / `_log_analysis_run` 把约 10 条 tool_call 记录合并为一次批量插入。

**2d. HTTP 客户端复用与重试收敛。** `model_adapter.py`、`embedding_adapter.py` 改为模块级共享 `httpx.Client`（按 base_url 缓存，线程安全）；重试仅针对 408/429/5xx 与传输异常，401/404/422 立即失败。

**2e. 提示词去重。** `model_sql_generator.py`：`_compact_question_intent` 不再携带 `query_plan`/`query_spec`/`resolved_contracts`（顶层已有）；`metric_semantics` 只发送计划内指标；去掉 `indent=2`。

## 阶段三：后端正确性与安全（对应报告 §3.1、§3.2、§3.4）

**3a. Guard AST 写检查。** `sql_validation_tools.py`：AST 遍历拒绝 `Insert/Delete/Update/Merge` 与 `SELECT ... INTO`；`BLOCKED_FUNCTIONS` 补 `pg_terminate_backend`、`pg_cancel_backend`、`lo_import`、`lo_export`、`set_config`。

**3b. 意图校验 AST 化（守住行为的定向修复）。** `analysis_graph.py`：`_sql_has_time_bounds` 先用 sqlglot 规范化 SQL 再匹配（覆盖 `::date`、`BETWEEN`、反序操作数）；`_token_present` 的指标口径检查改为基于 AST 的聚合函数 + 列识别（复用 `sql_inspector` 的别名解析），不再依赖写死的 `u.`/`o.` 别名。`_context_table_coverage` 收窄到 `query_plan["entities"]`。

**3c. 认证与限流。** `dependencies.py`：会话解析结果缓存到 `request.state`，`require_csrf` 复用而非二次查询；`auth_service.touch_session` 节流（60 秒内不重复写）；`auth_rate_limiter.py` 内存分支增加过期键淘汰、只计失败尝试；开发主体默认角色由 `admin` 降为 `developer`（`require_role("admin")` 的用例需显式开启）→ **注**：为避免破坏现有 claim-development 流程与测试，本轮保留 admin 默认但增加显著启动警告日志，降级建议写入文档。

**3d. 静默异常可观测化。** `vector_retrieval.py`、`context_builder.py` 的 `except Exception` 分支加 `logger.warning(..., exc_info=True)`，并在返回的诊断信息中标记 `degraded`。

## 阶段四：新增测试

连接池：并发借用/归还、损坏连接重建、池耗尽阻塞语义。Guard：CTE 写绕过（`WITH d AS (DELETE ...) SELECT ...`）必须被拒、`SELECT INTO` 必须被拒、新增黑名单函数必须被拒、正常 CTE SELECT 仍放行。Embedding 一次化：一次分析全程 embedding adapter 仅被调用一次（计数 stub）。时间边界校验：`::date`、`BETWEEN`、`DATE 'x' <= col` 反序均不再误报；缺时间条件仍告警。指标口径：非 `u`/`o` 别名的正确 SQL 不再误报。批量日志：一次 run 的 tool_calls 单连接写入且条数正确。限流器：成功登录不再占用配额、过期键被清理。全量套件回归绿。

## 阶段五：前端

**5a. 安全修复。** vite `server.proxy` 同源代理（`/api` → 127.0.0.1:8000），`API_BASE_URL` 默认空串；ECharts 改 `echarts/core` 按需注册（pie/line/bar + tooltip/legend/grid）；路由级 `errorElement` + 图表局部 error boundary；消息 ID 改 `crypto.randomUUID()`；SSE 客户端按规范合并多行 `data:`、增加每事件空闲超时（默认 60s，可配）。

**5b. ChatPage 重构改版。** 拆分：`useConversations()`（会话列表/分页/搜索/认领）、`useChatStream()`（SSE 生命周期/阶段事件/取消）两个 hook；`SessionSidebar`、`MessageList`、`MessageBubble`、`AnalysisDetails` 组件。布局改版：答案与图表优先展示，SQL/执行轨迹/来源折叠进 tabs 的"详情"区（渐进披露）；流式阶段进度条使用真实阶段名与耗时；表格数字千分位与货币格式化；统一空态/加载态。流式 stage 事件只更新独立的 streaming 状态切片，不再整表 map 消息数组。

**5c. 验证。** 沙箱内 `npm install` + `tsc --noEmit` + `vite build` 通过；页面组件保持原路由与 props 契约。

## 阶段六：回写与交付

所有修改文件经 device 桥回写本地工作区（不动 git）；输出变更清单（文件 × 改动摘要 × 对应报告条目）、测试结果（基线 vs 重构后）、以及建议的人工验收步骤（本机起前后端跑一次 smoke 问题）。

## 明确不做（本轮范围外）

图控制流重排（memory-first 快路径）、best-of-N 生成、memory_update 异步化——涉及行为变化，留待下一轮带评测对照做。评测体系（run_eval.py）改造。数据库索引与清理任务（需在本机 Postgres 上执行，随附 SQL 建议脚本但不自动执行）。`analysis_graph.py` 大拆分（仅做定向修复，避免大范围移动代码）。
