# 优化重构变更说明（2026-07-26）

按《项目优化实施计划》完成：后端 P0 + 安全 P1，前端安全修复 + ChatPage 重构。全部改动已写入工作区（未触碰 git），可用 `git diff` 逐一审查、`git checkout -- <file>` 回滚任意文件。

## 测试结果

云沙箱内搭建了 PostgreSQL + 完整迁移 + 种子数据环境实际执行：重构前基线 316/318 通过（2 个失败源于沙箱缺文件，后补齐）；重构后全量 **347/347 通过（0 失败）**，其中含新增回归测试 25 个（backend/tests/test_optimization_refactors.py）。测试套件总耗时从 72 秒降至 31 秒——主要来自连接池与会话查询去重。前端 `tsc --noEmit` 0 错误。

注意：沙箱无 pgvector 与真实模型端点，向量检索与 LLM 调用路径按项目自身的降级逻辑执行；建议在本机再跑一次 `npm run backend:test` 与一次完整评测做最终确认。

## 后端变更（对应分析报告条目）

**db/connection.py（§2.2）** 重写为有界连接池（默认 5，`DB_POOL_SIZE` 可配），`get_connection()` 契约不变；异常路径连接直接丢弃、归还前 rollback 复位；`.env` 路径改为相对文件定位，任何工作目录启动都能加载。每次分析约 15~25 次 TCP 握手降为复用。

**run_repository / run_logger / analysis_graph（§2.2c）** 新增 `create_tool_calls` / `log_tool_calls` 批量接口，一次分析约 10 条工具日志由 10 个连接合并为单连接 executemany。

**vector_retrieval / metric_retriever / schema_retriever / context_builder / sql_memory_tools / analysis_graph（§2.1）** 问题只 embed 一次：图入口计算 `question_vector` 存入状态，三路召回与记忆写入全部复用；记忆写入只为 SQL 文本补一次 embedding。每题 3~4 次远程 embedding 调用降为 1~2 次。检索路径的静默 `except` 全部补了告警日志（§3d）。

**http_client.py（新增）+ model_adapter / embedding_adapter（§P1）** 进程级共享 httpx.Client（keep-alive/TLS 会话复用）；重试只针对 408/429/5xx 与传输异常，401/404/422 立即失败不再空转重试。

**model_sql_generator.py（§2.5）** 提示词去重：`question_intent` 不再重复携带 `query_plan`/`resolved_contracts`（顶层唯一承载，未折叠时自动兜底进 `contract_constraints`）；`metric_semantics` 只发送与本题相关的指标（无法判断时保留全部）；JSON 载荷去掉 `indent=2`（约省 30% token）。

**sql_validation_tools.py（§3.1）** Guard 增加 AST 级写操作拦截：`WITH d AS (DELETE ...) SELECT ...` 这类藏在 CTE 里的写语句、`SELECT ... INTO` 均被拒绝；黑名单函数补 `pg_terminate_backend`、`pg_cancel_backend`、`pg_reload_conf`、`lo_import/lo_export`、`set_config`。

**analysis_graph.py 校验器（§3.2）** `_sql_has_time_bounds` 先经 sqlglot 规范化再匹配，`'x'::date`、`CAST`、`BETWEEN`、操作数反序均不再误报；指标口径检查改为 AST 解析 `COUNT(DISTINCT 表.列)`（任意表别名均可识别，删除写死的 `u.`/`o.`）；存在 Query Plan 时上下文表覆盖检查交由 Inspector 按 `plan.entities` 精确判定，过度召回不再触发多余的修复 LLM 调用。

**dependencies.py / auth_service.py / auth_rate_limiter.py（§3.4）** 会话解析每请求只查一次库（缓存于 `request.state`，`require_csrf` 复用）；`touch_session` 60 秒节流；限流器改为"失败才计数"（成功登录不再消耗限额）、内存回退分支超阈值自动清理过期 key。

**embedding_sync_service.py** `def _chunks[T]` PEP 695 语法改为 `TypeVar` 写法，兼容 Python 3.11+。

**测试** `test_optimization_refactors.py` 新增 25 个用例覆盖上述全部改动；`test_auth.py`、`test_model_sql_generator.py` 中两处断言旧行为的用例同步更新为新语义（文件内有注释说明）。

## 前端变更

**配置与网络** vite 增加 `/api` 同源代理（127.0.0.1:8000），`API_BASE_URL` 默认空串——消除 localhost/127.0.0.1 双 Cookie 罐导致的随机掉登录；SSE 客户端按规范拼接多行 `data:`、增加 60 秒每事件空闲超时（模型挂起不再永久卡住）。

**性能** ECharts 改为 `echarts/core` 按需注册（line/bar/pie + grid/tooltip/legend），入口包显著减小；流式阶段进度存独立状态切片，阶段刷新不再重渲染整个消息数组。

**健壮性** 新增 ErrorBoundary（路由级 + 图表局部），坏图表 spec 只影响单条消息不再白屏；消息 ID 改 `crypto.randomUUID()`；打开会话失败不再清空当前消息，改为内联提示。

**ChatPage 重构** 509 行 → 127 行：拆出 `useConversations` / `useChatStream` 两个 hook 与 `SessionSidebar` / `MessageList` / `MessageBubble` / `AnalysisDetails` 组件。布局改为渐进披露：答案与图表优先，SQL / 执行过程 / 来源收进默认折叠的 tab；流式期间展示阶段进度 + 实时秒数 + 骨架屏。数字千分位与 ¥ 格式化（`lib/format.ts`）。
